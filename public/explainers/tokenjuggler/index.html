The big idea

A helper who always finds a shop with room

Your app wants to ask a very smart robot a question. The robot is GPT, Gemini or Claude. Lots of different shops sell time with that robot, but every shop only lets you ask so many questions a minute. If you knock on a full shop, it says "No".

You ask

"Please summarise this."

Many shops

Each one has its own limit and its own price.

The juggler

Picks a shop that has room, and tries another if one says "No".

The real names: a model is what you ask for (like gpt-5.6-sol). A deployment is one shop's door to it, with its own limit and price (like gpt-5.6-sol@bedrock).

    The notebook (it writes down every try)

    Things to notice: five calls at once never grab the same seat, because choosing a shop and saving the seat happen in one go (the real tool does this in one Redis script). If every shop is just full, a call waits for the first seat to come back (the real setting is max_wait_seconds; here it is a pretend 8 seconds).

    Toy 2 · slide it

    Save a seat before you sit

    Before every call, the juggler saves a seat big enough for the longest answer you allow (that is max_output_tokens). That way the answer can never be bigger than the seat, so the shop's limit is never broken by surprise.

    Here is a call that runs into trouble. Press Next to see each step.

    If every shop for a model fails, the juggler can move on to the model's fallbacks, which is a different model you listed. It does not retry the same shop unless you turn retrying on.

    Toy 4 · slide it

    Bucket or window?

    A shop says "100 per 10 seconds". There are two ways to count that. A token bucket fills up slowly and lets you pour a whole bucket at once. A sliding window looks at any 10 seconds and never lets you go over. Drag the burst slider and look at the lines.

    The default is the token bucket, which is how OpenAI and Anthropic describe their limits. The sliding window is the strict one, for providers that count that way. Either way the tool keeps a safety margin under the limit (headroom, 0.95 by default). The numbers in this toy are made up to show the idea.

    Toy 5 · click the projects

    Sharing one pizza

    Many apps ("projects") can share the same shop accounts. Each project can get a cap, the most it may ever eat, and a reserve, a slice that is kept just for it. An idle project can lend its reserved slice to a busy one. Click a project to make it busy or idle.

    This is a simplified picture of the idea. The real rules are in the admin guide in the repository.

    Big words, small words

    Cheat sheet

    Quota
    How much a shop lets you use in a minute.
    429
    The shop shouting "too busy, come back later!"
    Failover
    Trying the next shop when one says no or breaks.
    Retry-After
    How long a shop says it needs to rest. The juggler leaves it alone that long.
    Redis
    A shared notebook that many copies of your app can read, so they all count together.
    Atomic
    Done all in one go, so nobody can cut in line halfway.
